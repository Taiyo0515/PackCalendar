## 2. データモデル（version 3）

```ts
type Where = string | null;          // バッグID | "home" | "worn" | null(不明)

interface Bag   { id: string; name: string; color: BagColor; itemIds: string[] }   // itemIds = 基本セット
interface Item  { id: string; name: string; photoId: string | null; at: Where; atTime: string /* ISO */; return: boolean }

interface Plan  { bagId: string | null; add: string[]; remove: string[]; extra: string[] }

interface Repeat { freq: "daily" | "weekly" | "monthly"; weekdays: number[] /* weekly のみ 0-6 */; until: string | null }

interface Event {
  id: string; title: string;
  start: string;            // "YYYY-MM-DDTHH:mm"（終日は T00:00）
  end: string | null;       // 終日は最終日の翌日 T00:00。null は開始時刻のみ
  allDay: boolean; memo: string;
  calendar: "main" | "fixed";   // 表示を切り替えられる2つのカレンダー
  plan: Plan; repeat: Repeat | null;
}

type Patch = Partial<Pick<Event, "title" | "start" | "end" | "allDay" | "memo" | "calendar">> & { plan?: Partial<Plan> };
interface Exception { deleted: boolean; patch: Patch }        // キーは `${eventId}@${YYYY-MM-DD}`

interface Settings {
  weekStart: 0 | 1; holidays: boolean; auto: boolean;
  theme: Theme; widgetTheme: Theme;                         // Theme = "system" | "light" | "dark"
  hidden: CalendarId[];                                     // 既定は ["fixed"]
  remind: { on: boolean; evening: string | null; morning: string | null };
}

interface State {
  version: 3;
  bags: Bag[]; items: Item[]; events: Event[];
  exceptions: Record<string, Exception>;
  settings: Settings;
  cursor: string;           // 自動記録を最後に反映した時刻（ISO）
}
```

- ID は `crypto.randomUUID()`。
- 日時は端末のローカル時刻の文字列で扱う。繰り返しは現地の日付と時刻で展開する。
- `atTime` は位置を最後に変えた時刻。自動記録で「開始時刻より後に手で直した物を上書きしない」判定に使う。
- `calendar` と `settings.hidden` は表示だけに使う（`showsCalendar`）。準備・通知・予測はどちらのカレンダーも同じに扱う。既定値があるので、これらがない古い保存データもそのまま読める。
- 保存前に zod で検証し、参照（バッグ・持ち物の ID）の整合も確かめる。不正なら保存しない。

## 3. アルゴリズム

### 3.1 予定の展開 `occurrences(state, from, to)`

1. 各予定について、`from〜to` の日に当たる回を列挙する。
   - 繰り返しなし：開始日だけ。
   - daily：毎日。weekly：`weekdays` に含まれる曜日。monthly：開始日と同じ日付（ない月は飛ばす）。
   - `until` を過ぎた日は除く。
2. その日の変更（`exceptions`）があれば適用する。`deleted` なら除く。`plan` はフィールド単位で上書きする。
3. 複数日にまたがる予定は、期間に重なる日すべてに表示する。展開の開始日は、予定の長さぶん前にずらして探す。
4. 開始時刻の順に並べる（終日を先に）。

回のキーは `${eventId}@${開始日}`。

表示（月のカレンダー・日のシート・ウィジェットのカレンダー）は、この結果から `settings.hidden` に入っているカレンダーの回を除きます（`visibleOccurrences`）。準備の計算は除きません。

### 3.2 準備 `units(state, occurrences)`

```
for 予定 in 開始時刻順:
  if バッグなし: 現在の準備を閉じる; continue
  if 現在の準備があり、同じバッグで、同じ日: 追加する
  else: 新しい準備を始める
```

準備の必要な物は、含まれる予定の必要な物の和集合です。

### 3.3 移す物 `moves(state, unit)` → `Line[]`

```ts
interface Line { kind: "bag" | "home" | "unknown" | "extra"; label: string; names: string[]; itemIds: string[] }
```

移動元のバッグごと、自宅、不明、今回だけ、の順に並べます。

### 3.4 自動記録 `advance(state, now)`

```
units = 準備(occurrences(cursor の日 〜 now の翌日))
moves = 各 unit を「開始」と「終わり」の2つの動きに広げた時系列
for m in moves で cursor < m.t <= now:
  開始の動き: for 持ち物 in unit.必要な物:
    if 持ち物.atTime <= m.t かつ 身につけていない: 持ち物.at = unit.bag; 持ち物.atTime = m.t
  終わりの動き: for 持ち物 in unit.必要な物:
    if 持ち物.return かつ 持ち物.at == unit.bag かつ 持ち物.atTime <= m.t:
      持ち物.at = 自宅; 持ち物.atTime = m.t
cursor = now
```

`auto` がオフのときは `cursor` だけを進めます（オンに戻したとき、過去の分を一度に反映しないため）。

Unit の「終わり」は、まとめた予定の中で分かっている最も遅い終了時刻、どの予定にも終了時刻がなければ翌日の午前0時です。

### 3.5 先の予測 `forecast(state, now, days)`

状態を複製し、30日前から `days` 日先までの準備を時系列に処理します。`now` より後の動きだけを仮に反映します（それ以前の記録は現在の位置にすでに反映済み）。準備の中には「開始」と「終わり」の2つの動きがあるので、まだ使っている途中の「使ったら自宅に戻す」物は、先の準備では自宅にあるものとして計算します。通知の予定表とウィジェットのデータは、この結果から作ります。

### 3.6 祝日 `holidays(year)`

- 固定日：元日、建国記念の日、天皇誕生日（〜2018 は 12/23、2020〜 は 2/23）、昭和の日（2007〜。それ以前はみどりの日）、憲法記念日、みどりの日（2007〜 5/4）、こどもの日、山の日（2016〜）、文化の日、勤労感謝の日。
- ハッピーマンデー：成人の日（1月第2月曜）、海の日（7月第3月曜）、敬老の日（9月第3月曜）、スポーツの日（10月第2月曜。2019 年までは体育の日）。
- 春分・秋分：`floor(20.8431 + 0.242194(y−1980) − floor((y−1980)/4))`、`floor(23.2488 + …)`。
- 特例：2019/5/1・10/22（即位関連）。2020 年は海の日 7/23、スポーツの日 7/24、山の日 8/10。2021 年は 7/22、7/23、8/8。
- 振替休日：祝日が日曜なら、その後の最初の祝日でない日。
- 国民の休日：前後の日が祝日で、その日が祝日でも日曜でもない日。
- 年ごとに結果を記憶して再計算しない。

## 4. 保存

### 4.1 IndexedDB

- DB 名：`packcalendar3:${パス}`（公開 URL のパスごとに分ける）。
- テーブル：`kv`（`state`、`push`、`lastBackup` などの設定値）、`photos`（`{ id, bytes: ArrayBuffer, type }`）。
  - 写真は Blob ではなく ArrayBuffer で保存する（WebKit の Blob 保存の不具合を避ける）。
- 保存は `state` を丸ごと置き換える。`revision` を持たせ、別のタブがより新しい内容を保存していたら上書きせずに読み直す。
- 別のタブの変更は Dexie の `liveQuery` で受け取り、表示に反映する。

### 4.2 旧 v2 からの取り込み

- `state` がなく、旧 DB（`packcalendar:${パス}` の `states.current`）があれば変換して保存する。旧 DB は消さない。
- 変換規則：
  - `containers`（kind=bag）→ `bags`。色は sage→green、sand→orange、blue→blue、rose→pink、plum→purple。
  - 名前付きの場所（kind=place、home 以外）にある持ち物 → 位置は「自宅」。
  - `items.location.containerId` → `at`、`location.updatedAt` → `atTime`、`imageId` → `photoId`。
  - `events`：`startAt/endAt` → `start/end`、`recurrence/weekdays/until` → `repeat`、`plan.addedItemIds` などを短い名前へ。カテゴリ・メモ以外の旧項目は捨てる。カレンダーは「通常」にする（既存の予定は移さない）。
  - `overrides` → `exceptions`。
  - `settings`：週の始まり・自動記録・通知時刻を引き継ぐ。
  - 論理削除された物（`deletedAt` あり）は取り込まない。
- 写真：旧 DB の `photos` から、参照されているものだけ写す（Blob・ArrayBuffer の両方に対応）。

### 4.3 バックアップ

```json
{ "app": "PackCalendar", "format": 3, "exportedAt": "…", "state": { … }, "photos": { "id": "data:image/jpeg;base64,…" } }
```

読み込みは format 3 と旧 format 2（v2 の書き出し）に対応します。format 2 は 4.2 と同じ規則で変換します。

### 4.4 取り込み

- **ICS（Google カレンダーの秘密の iCal アドレス）**：`src/core/ics.ts` が最小限の VEVENT パーサを持つ。改行の復元、日付の種類、`RRULE` のうち本アプリに置き換えられる形だけを拾い、`EXDATE`・`STATUS:CANCELLED`・`RECURRENCE-ID`（同じ日の中での変更のみ）を拾う。
- **TimeTree**：Web 版と同じ端点（`timetreeapp.com/api/v1`）を `_session_id` Cookie で読む。カレンダー一覧を表示して選び、`events/sync` をカーソル順に追う。応答の形は非公開なので、項目名は前方一致で緩く拾う。
- **端末のカレンダー**：PackBridge に `readCalendar` を追加。EventKit の `predicateForEvents` で展開済みの予定を取り、繰り返しは `EKRecurrenceRule` から本アプリの形に写す。毎年・第〇週などの置けない形は繰り返しなしにする。iOS 17 以降は `NSCalendarsFullAccessUsageDescription`（16 以前向けに `NSCalendarsUsageDescription` も）が必要。
- **合流**：`src/core/import.ts` が「元の識別子から ID を作る」（SHA-256）ので、再取り込みは追加でなく更新になる。取り込む前に件数を確認させ、合流は 1 回の保存で行う。
- **経由**：Google・TimeTree はブラウザから直接読めない（CORS と距離）ため、通知ワーカーに `POST /import` を追加した。ホストは calendar.google.com と timetreeapp.com の2か所に絞り、取り込みコード（`X-Invitation`）を要求する。Capacitor アプリの原本（`capacitor://localhost`）も受け付ける。

## 5. 通知

- 予定表 `{ id, at(ISO), title, body, url: "#home" }[]`（最大60件、14日先まで）。
- **Web**：既存の Worker の API をそのまま使う。
  - `GET /config` で公開鍵を取得 → `pushManager.subscribe` → `POST /device`（`X-Invitation`）で端末 ID とトークンを受け取る → `PUT /schedule` で予定表を全置換 → 停止は `DELETE /device`。
  - 接続先 URL はビルド時の `VITE_PUSH_URL`。画面では招待コードだけを入力する。
  - 予定表の内容をハッシュ化して保存しておき、変わったときだけ送る。
- **iPhone アプリ**：`@capacitor/local-notifications`。予約済みを全部取り消してから、予定表を登録し直す。
- Service Worker は、ビルドのたびにファイル一覧のハッシュでキャッシュ名を変える（既存の方式を踏襲する）。

## 6. iPhone アプリ

### 6.1 Capacitor

- `appId`：`io.github.taiyo0515.packcalendar`。`webDir`：`dist`。
- `ios.contentInset`：`never`。安全領域は CSS の `env(safe-area-inset-*)` で空ける。
- プラグイン：local-notifications、filesystem。カメラは `<input type="file" accept="image/*">` で撮影できるため、camera プラグインは外す。
- 写真の入力、通知、バックアップ以外は Web と同じコードで動かす。

### 6.2 PackBridge（アプリ内の独自プラグイン）

| メソッド | 動作 |
|---|---|
| `saveWidget({ json })` | App Group のフォルダに `widget.json` を書き込み、`WidgetCenter.shared.reloadAllTimelines()` を呼ぶ |
| `setAppearance({ mode })` | ウィンドウの `overrideUserInterfaceStyle` を設定する（ステータスバーの色を合わせる） |

- `MainViewController`（`CAPBridgeViewController` の子クラス）の `capacitorDidLoad()` でプラグインを登録する。画面は `SceneDelegate` がコードで作るため、そこで `MainViewController()` を生成する（`Main.storyboard` の customClass も合わせて変える）。
- Web 側は `registerPlugin("PackBridge")` で呼ぶ。Web のときは呼ばない。

### 6.3 App Group の解決（SideStore 対策）

SideStore は署名し直すときに App Group の ID を書き換えます（チーム ID が付く）。どのバンドルにどの手がかりが残るかは保証されないため、ID を1つに決め打ちしません。アプリ本体とウィジェットで同じ `SharedGroup.swift` を使います。

- 候補の ID を集める：自分のバンドルと（ウィジェットなら）親アプリのバンドルの、Info.plist の `ALTAppGroups`、`embedded.mobileprovision` の `com.apple.security.application-groups`、`group.` ＋アプリのバンドル ID、ビルド時の `group.io.github.taiyo0515.packcalendar`。
- アプリ：候補のうち、実際に書き込めたすべてのコンテナに `widget.json` を書く。1つも書けなければエラーにする。
- ウィジェット：読めたファイルのうち、更新日時が最も新しいものを使う。
- 書き込めない・読めないときは、設定画面の「外観」の下に原因（候補の ID）を表示する。問題がなければ何も表示しない。

### 6.4 ウィジェットのデータ（`widget.json`）

```json
{
  "v": 1,
  "theme": "system",
  "weekStart": 0,
  "generatedAt": "2026-09-27T12:00:00+09:00",
  "units": [
    { "start": "2026-09-28T09:00", "title": "大学で作業", "bag": "リュック", "color": "#1E9E6A",
      "lines": [ { "label": "ミニバッグから", "names": "財布・鍵" } ] }
  ],
  "days": { "2026-09-28": [ { "t": "大学で作業", "c": "#1E9E6A" } ] },
  "holidays": { "2026-09-21": "敬老の日" }
}
```

- `units`：先の予測（3.5）で作った14日分の準備。
- `days`：今月の前後を含む6週分と、翌月・翌々月の6週分（ウィジェットが月をまたいでもしばらく表示できるように）。表示していないカレンダーの予定は入れない。
- JS の変更のたびに、500ms まとめてから書き込む。

### 6.5 WidgetKit 拡張（`PackWidget`）

- iOS 17 以上。`StaticConfiguration` を2種類：`PrepWidget`（`.systemSmall`）、`CalendarWidget`（`.systemLarge`）。
- タイムライン：現在、各準備の開始時刻、翌日の 0:00 にエントリを作る。更新方針は `.atEnd`。
- 外観：`theme` が light・dark ならその色、system なら `@Environment(\.colorScheme)` に従う。背景は `containerBackground(for: .widget)`。
- 日付の計算は `Calendar(identifier: .gregorian)` と端末のタイムゾーンで行う。

### 6.6 Xcode プロジェクトへの追加

Windows では Xcode を動かせないため、ウィジェットのターゲットは CI（macOS）で Ruby の `xcodeproj` gem を使って追加します（`scripts/ios/add_widget_target.rb`）。

- 同じ名前のターゲットがあれば何もしない（何度実行しても同じ結果）。
- アプリ本体：`PackBridgePlugin.swift`・`MainViewController.swift`・`SharedGroup.swift` を追加し、`CODE_SIGN_ENTITLEMENTS = App/App.entitlements` を設定する。
- ウィジェット：`app_extension` ターゲット、バンドル ID `io.github.taiyo0515.packcalendar.widget`、iOS 17.0、WidgetKit・SwiftUI。アプリ本体の「Embed Foundation Extensions」に組み込む。

### 6.7 署名とパッケージ

- `xcodebuild` は署名なしでビルドする（`CODE_SIGNING_ALLOWED=NO`）。
- その後、`codesign -s -`（アドホック署名）で、エンタイトルメント（App Group）を実行ファイルに埋め込む。順番は、Frameworks 内の各ファイル → ウィジェット → アプリ本体。SideStore はこのエンタイトルメントを読んで App Group を登録する。
- `Payload/PackCalendar.app` を zip して `.ipa` にする。

### 6.8 SideStore での注意

- 無料の Apple ID では、アプリの拡張も App ID を使う。PackCalendar はアプリとウィジェットで2つ使う。
- 同時に使えるアプリの枠（SideStore を含めて3つ）を拡張が消費するかどうかは要確認。枠が足りない場合は、SideStore の「拡張を削除」を選べばウィジェットなしで動く。

## 7. CI（GitHub Actions）

### 7.1 `pages.yml`（main への push）

`npm ci` → `npm test` → `npm run build`（`VITE_PUSH_URL`）→ Playwright（Chromium と iPhone 相当の WebKit）→ Pages に公開。

### 7.2 `ios.yml`（ふだんのリリース: `ios-v*` タグへの push と、手動実行）

```
runs-on: macos-latest
npm ci → npm run build → npx cap sync ios
→ gem install xcodeproj → ruby scripts/ios/add_widget_target.rb
→ bash scripts/ios/build.sh（xcodebuild・codesign・zip）
→ 成果物（ipa、ビルドログ）をアップロード
→ タグのときは gh release create でリリースに ipa を添付（permissions: contents: write）
```

### 7.3 `package.yml`（依頼があったとき: `v*` タグへの push と、手動実行）

```
jobs:
ipa:   runs-on: macos-latest
       npm ci → npm run build → npx cap sync ios
       → gem install xcodeproj → ruby scripts/ios/add_widget_target.rb
       → bash scripts/ios/build.sh（xcodebuild・codesign・zip）→ ipa をアップロード
apk:   runs-on: ubuntu-latest
       setup-java 21 → npm ci → npm run build → npx cap sync android
       → ./gradlew assembleRelease（versionCode=実行番号）→ APK をアップロード
publish: needs: [ipa, apk]
       ダウンロードした ipa と apk を、タグ名のリリースに pre-release として添付
```

1 つのバージョンに ipa と apk をまとめたリリースを 1 つ作る。ふだんは §7.2 の ipa だけを配り、§7.3 は依頼があったときだけ使う。

バージョンは `package.json` の `version` を `MARKETING_VERSION` と versionName、実行番号を `CURRENT_PROJECT_VERSION` と versionCode にします。

Codemagic の設定（`codemagic.yaml`、`scripts/publish-ios.mjs`）は削除します。

## 8. Android アプリ

iOS 版と画面・ドメインは共通。`src/platform/native.ts` の `PackBridge` インターフェイスを同じ実装にする。

| iOS | Android |
|---|---|
| PackBridgePlugin.swift | `PackBridgePlugin.java`（同じ4つのメソッド） |
| App Group + `widget.json` | SharedPreferences `widget` の `widget.json`（アプリとウィジェットは同プロセスなので1か所で足りる） |
| EventKit 読み取り | `CalendarContract`（RRULE を同じ制限で写す。誕生日・端末同梱の祝日カレンダーは除外） |
| WidgetKit 拡張 | `PrepWidgetProvider`（RemoteViews）と `CalendarWidgetProvider`（Canvas で bitmap 描画）。更新は書き込み時・30分周期・0時・次の単位開始のアラーム |
| 未署名 ipa + SideStore | 署名済み APK。署名鍵は `android/app/packcalendar.keystore` をリポジトリに入れて毎回同じ署名にする |

アプリアイコンとスプラッシュは `scripts/android/icons.ps1` が `public/assets/icon-512.png` から生成する。

## 9. テスト

| 対象 | 方法 |
|---|---|
| core（日付・祝日・展開・例外・準備・移す物・自動記録・予測・通知文・ウィジェットデータ・移行） | `node --test`（tsx）で単体テスト |
| 保存（読み書き・旧 v2 取り込み・バックアップ往復） | fake-indexeddb で単体テスト |

| 画面 | Playwright：予定の追加・編集・繰り返しの「この予定のみ」、準備カード、バッグ画面の出し入れ、持ち物の登録、設定の切り替え、ダーク、文字が選択できないこと、スマホで予定名が見えること |
| iOS | GitHub Actions でビルドが通ること。実機の確認項目は 05 に記載 |
| Android | GitHub Actions で APK ビルドが通ること。ウィジェット・取り込み・通知は実機で確認する |
