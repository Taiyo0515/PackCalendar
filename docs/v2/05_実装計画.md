# 05 実装計画

## 1. 進め方

既存の UI（`src/ui`、`src/App.tsx`、`src/design.css`）とドメイン（`src/core`）は作り直します。流用するのは次の部分だけです。

| 流用する | 理由 |
|---|---|
| `worker/`（通知サーバー）と、その API | 公開済みで動作が確認されている |
| Web Push の接続手順（旧 `src/platform/web.ts`） | Worker の API に合わせた実装 |
| 写真の縮小（旧 `src/platform/photos.ts`） | 単純で問題がない |
| Service Worker の生成（`scripts/build-sw.mjs`、`src/platform/service-worker.js`） | 動作が確認されている |
| `ios/` の Capacitor プロジェクト | macOS でのビルド実績がある |

削除するもの：`src/legacy/`、旧テスト（`tests/browser`、`tests/core.test.mjs`、`tests/v2`、`tests/e2e`）、`release/`、`codemagic.yaml`、`scripts/publish-ios.mjs`、`PackCalendar-pages.zip`、旧版の検証用スクリプト。

## 2. 作業の順番

1. **core**：date → holidays → model → calendar → prep → schedule → migrate。単体テストを先に通す。
2. **platform**：store（取り込み・バックアップを含む）→ photos → push → native → index。
3. **UI 部品**：styles.css（トークン・ダーク・選択禁止）→ kit.tsx。
4. **画面**：App → Calendar（準備カード・月・日パネル）→ DaySheet → EventView → EventEditor → Things → BagView → ItemEditor・BagEditor → Settings。
5. **iOS**：PackBridge・MainViewController・SharedGroup・Main.storyboard → PackWidget（Swift）→ Ruby スクリプト → build.sh → ios.yml。
6. **CI・文書**：pages.yml、README、決定ログ、旧文書の整理。
7. **検証**：単体テスト、Playwright（スマホ・PC、ライト・ダーク）、スクリーンショットでの目視確認。

## 4. 実機での確認手順（iPhone）

1. GitHub の Actions から「Build iOS IPA」を実行し、成果物の ipa を取得する（またはタグ `ios-v3.0.0` のリリースから取得する）。
2. SideStore で ipa をインストールする。拡張を削除するか聞かれたら「残す」を選ぶ（3つの枠が足りない場合だけ削除する）。
3. アプリを開き、バッグ・持ち物・48時間以内の予定を登録する。
4. ホーム画面を長押し → ＋ → PackCalendar から、準備リスト（小）とカレンダー（大）を追加する。
5. 表示が正しいこと、アプリで予定を変えるとウィジェットも変わること、設定の外観でウィジェットの色が変わることを確認する。
6. 通知をオンにして、前日・当日の時刻に通知が届くことを確認する。
